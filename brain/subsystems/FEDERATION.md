# FEDERATION.md — Federated ships (the fleet)

A **ship** is a subsystem with its own captain, crew, contract, and `AGENTS.md` under `brain/subsystems/<ship>/`. Ships coordinate with the core and with each other only through the shared **Link** ledger — they never reach into another ship's state or into `brain/state/`.

The canonical example is the **Logos** deep-research ship (captain Niobe, crew Ghost + Sparks). The core vessel is the **Nebuchadnezzar**.

## 1. What a ship is

- Owns a capability discipline that would bloat the core roster (e.g., deep research with evidence grading).
- Has a single captain who is the only voice of the ship toward the core.
- Keeps its own `AGENTS.md` with a YAML frontmatter manifest.
- Is lazy-loaded: Neo routes to the captain only when the `route-when` trigger fires.

## 2. The manifest schema

Each `brain/subsystems/<ship>/AGENTS.md` begins with a frontmatter block:

```yaml
---
ship: <ship-slug>
captain: <captain-agent>
crew: [<agent1>, <agent2>, ...]
crew-max: <N>
route-when: <prose trigger criteria>
writes: [<event:namespace>]
reads: [<event:namespace>]
state: <relative-path-to-ship-state>
request: <event:namespace>
result: <event:namespace>
---
```

| Field | Meaning |
|---|---|
| `ship` | Ship slug (matches directory name). |
| `captain` | The ship's master; the only agent the core talks to. |
| `crew` | List of internal crew members; the captain may spawn them directly. |
| `crew-max` | Hard roster limit for this ship (3 for Logos). |
| `route-when` | Prosa criteria that Neo uses to decide when to route here. |
| `writes` | Event namespaces the ship writes to the ledger. |
| `reads` | Event namespaces the ship reads from the ledger. |
| `state` | Ship-local state path (must be gitignored). |
| `request` / `result` | Events the core and ship use to hand off work. |

## 3. Integration checklist

Run `bin/matrix hooks validate_ship '{"ship":"*"}'` to verify every ship. The hook is the source of truth for this checklist.

| # | Item | Verified by |
|---|---|---|
| 1 | Manifest parses and has all required keys | `validate_ship` check `manifest_parses` |
| 2 | Captain file exists and is a valid agent | `validate_ship` check `captain_present` |
| 3 | Crew files exist and are valid agents | `validate_ship` check `crew_present` |
| 4 | `len(crew) + 1 ≤ crew-max` | `validate_ship` check `roster_discipline` |
| 5 | Ship state is not under `brain/state/` and ship files do not mention it | `validate_ship` check `no_core_state` (heuristic) |
| 6 | Ship state path is gitignored | `validate_ship` check `state_gitignored` |
| 7 | Corpus has one appraisal per source and no self-grading | `validate_ship` check `corpus_shape` (when data exists) |
| 8 | Captain artifact carries the required delegation-depth grant; leaves do not | `validate_ship`'s delegation-depth check |

The `<ship>-<agent>` prefix, generated by `adapters/_build.py`, is the structural defense against name collisions. There is no `no_name_collision` check: it was removed from the design as redundant. Reopen the analysis if ship slugs with hyphens are admitted.

## 4. Coordination protocol

The core and a ship communicate through the Link ledger:

1. **Neo** writes `research:request <slug> --ref=<R>`.
2. **Neo** spawns the ship's captain once with the request.
3. **Captain** immediately before each dispatch logs `bin/matrix link crew:task <ship-slug> --ref=<R> "profile=<ship>-<agent> crew=<agent> topic=<topic> <free text>"`; the subject is only the ship slug, and `profile=`, `crew=`, `topic=`, and free text are detail. It then dispatches via the delegate capability and reads the crew's output back through it. `profile=` is the captain's declaration of intent before dispatch, not a runtime measurement: it does not prove what the adapter actually spawned, which is outside the ledger's scope.
4. **Captain** runs the integrity gate and writes `research:result <slug> --ref=<R>`.
5. **Neo** reads the result and presents it to the user.

`bin/matrix activity` filters by the resolved project by default. Ship events (whose subject is the ship slug) therefore do not appear in the default view; use `--all` or `--project=<ship>` to see them.

Neo never knows the crew members of a ship. The captain is the only surface.

## 5. Spawn-direct pattern (canonical)

Under the current adapter, a ship captain is generated with a nesting-depth grant (see the adapter's own reference doc and `capability-map.md` for the concrete field name) that authorizes it to spawn its crew. This removes the need for courier protocols like the old `CREW-ORDER`. Requirements:

- The captain declares `run-subagent` in its brain capabilities.
- The Trainman injects the required delegation-depth grant into the captain's generated artifact only (see the adapter's own reference doc for the concrete field name).
- Crew leaves do **not** carry a delegation-depth grant; they cannot spawn anything.
- If the captain cannot spawn a crew member, it aborts with `LOGOS_ABORTED: crew unreachable` and reports — never falls back to self-grading or self-ingesting.

## 6. Delegation depth

The required delegation-depth grant is derived from the ship manifest graph:

```text
required_nesting(agent) = depth_from_root(agent) + subtree_depth(agent)
```

- **Logos** (flat): Niobe is depth 1 from Neo, her crew is depth 2. Niobe's `subtree_depth` is 1 (direct leaves), so the required delegation-depth grant is 2. Ghost and Sparks have no children, so they get no field.
- The formula is **verified only for depth 2**. A ship with sub-captains (depth ≥3) requires a new nesting spike before the formula can be trusted.

## 7. Producer ≠ evaluator: where it is mandatory and where it is relaxed

Matrix holds **two different rules** about whether the actor that produced a thing may also grade it. This is a deliberate split, decided once and recorded here. It is not an inconsistency to reconcile — a future session that "fixes" it by making both sides match will break the side it did not think about.

**Mandatory, enforced in code — research artifacts (the fleet).** A ship may never grade its own output. `logos/agents/ghost.md:44` ("never grade a source you yourself ingested"), `corpus-spec.md:63` (`appraised_by` must be neither the captain nor any ingestor), checklist item 7 in §3 above, and the canonical spawn-direct requirement in §5 (a captain that cannot spawn crew **aborts**, never self-grades) all say the same thing, and `hooks/validate_ship.py`'s `corpus_shape` check **fails the ship** when an appraisal's `appraised_by` matches the captain or an ingestor. Actor separation is load-bearing here.

**Relaxed, compensated by evidence — code defects (the core roster).** The core's evaluator may fix the low-blast-radius defects it reported itself (Tier 1 inert, Tier 2 localized with an independent diff review before close; Tier 3 always goes back to the builder). See the evaluator's own `<rules>` for the tiers and the pre-registration protocol.

**Why the two rules differ — the actual reason, so it can be argued with instead of guessed at:** code has a **runtime oracle** and a research synthesis does not. A failing command that predates the fix, is not authored by the fixer, and is re-run verbatim afterward is an external reference frame: it can contradict the fixer. A prose synthesis has no such thing — the only available reference frame for "is this source any good" is *another mind*, so removing the second actor removes the entire check and leaves nothing. So the compensator differs by what is available: for code, separation **in time** (the oracle predates the fix); for research, separation **between actors**, because time buys nothing there.

**The invariant that unifies them,** and the one to preserve if either rule is ever revisited: *no artifact is graded by a reference frame that the producer controls.* Both rules are instances of it. Neither may be weakened to "the producer says it's fine".

**Consequences, so nobody has to re-derive them:**
- Never grant the fleet's evaluator-side agents an editing capability by analogy with the core's evaluator. The analogy does not hold, and `validate_ship`'s check would not catch a self-*ingest*-then-appraise done by one edit-capable agent.
- Never remove `validate_ship`'s self-grading check on the grounds that "the core allows self-fixing now". Different rule, different subject, different reason.
- A code fix whose only proof is a check the fixer wrote or modified is **not** covered by the relaxed rule. It is the mandatory rule's failure mode wearing a runtime-oracle costume, and it goes back to the builder.

## 8. Procedure: add a ship

1. Create `brain/subsystems/<ship>/AGENTS.md` with the manifest frontmatter.
2. Create `brain/subsystems/<ship>/agents/<captain>.md` and crew agents.
3. Define ship-local state (e.g., `corpus/`) and ensure `.gitignore` covers it.
4. Run `bin/matrix hooks validate_ship '{"ship":"<ship>"}'`.
5. Run `bin/matrix build --target=<cli> && bin/matrix install --target=<cli>`.
6. Re-run `validate_ship` and `the_source --check`.
